# Пример Web API приложения с CRUD методами

В Web API используется фреймворк .NET 6 и база данных PostgreSql. Для демонстрации взята сущность Patient (пациент).

## Пример сущности в формате JSON: 
```
{ 
 "name": 
 { 
    "id" : "d8ff176f-bd0a-4b8e-b329-871952e32e1f", 
    "use": "official", 
    "family": "Иванов", 
    "given": [ 
        "Иван", 
        "Иванович" 
    ] 
 }, 
 "gender": "male", 
 "birthDate": "2024-01-13T18:25:43", 
 "active": true 
}
```

**Примечание:** Данные в базе хранятся в двух таблицах: PatientEntity и PatientNameEntity. В поле "name" присутствует "id", информация о связях и полной структуре бд отсутствует, поэтому на основе JSON примера было принято решение разбить информацию на две таблицы со связью один к одному. Если "name" не используется как отдельная сущность в других таблицах, то правильнее хранить всю информацию о пациенте с именем в одной таблице.

## Обязательные поля: 
- name.family 
- birthDate

## Справочники: 
- Gender: male | female | other | unknown 
- Active: true | false

## Архитектура:
Трехслойная архитектура:
- *Слой доступа к данным* (EF Core уже реализует паттерн репозитория, поэтому этот слой можно исключить. Используется для структуризации проекта)
    - В качестве ORM используется Microsoft.EntityFrameworkCore Version="7.0.20".
    - Для подклчения к базе данных используется Npgsql.EntityFrameworkCore.PostgreSQL Version="7.0.18".
    - В данном слое находится настройка подключения к базе, настройка сущностей и связей, миграция базы данных.
- *Слой бизнес-логики*
    - Для гибкой валидации DTO используется FluentValidation Version="11.12.0".
    - В данном слое находится бизнес-логика приложения (сервисы), валидаторы и мапперы DTO и Entity Models.
- *Слой представления*
    - В данном слое находится конфигурация Web API приложения, контроллеры с эндпоинтами для взаимодействия с нашими сущностями, настройка контейнеризации.
    - Для документирования используется Swashbuckle.AspNetCore Version="6.5.0".

## Структура Решения:
1. Проект \ Слой доступа к данным.
2. Проект \ Слой бизнес-логики.
3. Проект \ Слой представления.
4. Тесты (покрыты не все кейсы, создана лишь часть тестов в качестве демонстрации и для проверки поиска по дате рождения).
5. Проект \ Консольное приложение для генерации тестовых данных через Web API (Альтернатива: использовать метод с генерацией данных в слое доступа к данным во время миграции).

## Postman коллекция
Хранится в папке "PatientApi.Web/PostmanCollection" в формате JSON.

## Запуск в Docker:
1. в appsettings.json проверить, что в строке подключения указано правильное имя хоста (Host=db);
2. из директории солюшена "../PatientApi" запустить команду "docker-compose -f PatientApi.Web/docker-compose.yml up --build";
3. вручную через Package Manager Console накатить миграцию базы данных "Update-Database".
